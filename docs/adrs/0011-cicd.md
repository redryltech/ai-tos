# ADR-0011: CI/CD — OIDC auth, security scanning, gated Terraform

- **Status:** Accepted
- **Date:** 2026-07-30
- **Deciders:** CTO / Architecture Review Board
- **Phase:** 0A (foundation decision; workflows updated now)

## Context

Phase 0A CI ran `lint/typecheck/build/test` with no cloud auth, no security/dependency/
image scanning, and a Terraform workflow that `init -backend=false` without AWS
credentials. The board (verdict: ⚠ APPROVED WITH CHANGES, Priority 8) requires hardened
CI/CD before Phase 0B.

## Decision

### Authentication — OIDC (no static keys)
- GitHub Actions federates to AWS via **OIDC** (`aws-actions/configure-aws-credentials`
  with `role-to-assume`, trust scoped to `repo:ai-tos/*` + branch/environment). No
  long-lived AWS keys in GitHub secrets. Same pattern for Terraform (ADR-0008) and ESO
  (ADR-0009).

### Security scanning (shift-left)
- **SAST:** CodeQL (and/or Semgrep) on every PR.
- **Dependency scanning:** Dependabot + Renovate (present) + `npm audit` / `pip-audit` /
  `govulncheck`.
- **Image scanning:** **Trivy** (filesystem + built images), fail pipeline on
  `HIGH`/`CRITICAL`; generate **SBOM** (Syft → CycloneDX).
- **IaC scanning:** **tfsec** / **Checkov** / **Trivy config** on `infrastructure/**`.
- **Signing:** **Cosign** sign images + SBOM; verify on deploy (admission policy later).

### Terraform strategy (separate, gated)
- `terraform plan` runs on every PR touching `infrastructure/terraform/**` using OIDC
  (no manual creds); plan posted as a PR comment.
- `terraform apply` runs **only** on `main` (or a protected `infra` environment) via
  GitHub **Environments** with **required reviewers** + `production` protection rules.
  No auto-apply from feature branches.
- Drift detection scheduled (optional later).

### App delivery
- Build → scan → sign → push to ECR → Argo CD (ADR-0007) reconciles via Kustomize
  overlays. Semantic-release on `main` for versioning/tags.

## Alternatives considered

- **Static AWS keys in secrets** — *Rejected* (current-adjacent): rotation burden, leak
  risk.
- **Manual `terraform apply`** — *Rejected*: no auditability, no plan gate.
- **Single combined pipeline** — *Rejected*: Terraform must be isolated and gated
  separately from app CI.

## Consequences

- No long-lived cloud credentials in CI.
- Vulnerabilities caught before merge/deploy; images signed & attributable (SBOM).
- Terraform changes are reviewed (plan) and gated (apply with approval).
- Slightly longer pipelines; required reviewers add a human gate for prod.
